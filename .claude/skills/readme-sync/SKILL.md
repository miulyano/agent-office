# README совпадает с кодом

Устаревший README хуже, чем его отсутствие: он вводит в заблуждение. Перед `git push` проверить разделы, которых коснулись изменения.

| Что поменялось | Раздел README |
|---|---|
| Флаги `argparse` в `server.py`, переменные окружения | «Команды» |
| Скрипты в `scripts/`, команды в `package.json` | «Установка», «Команды» |
| Адреса в `do_GET` и `do_POST` | «HTTP API» |
| Константы `THINK`, `COFFEE`, `DONE`, `AWAY`, `AGENT_IDLE_S` | «Кто чем занят» |
| Модели в `PRICES` и `gradeOf` | «Кто есть кто» |
| Новые файлы или папки | «Где что лежит», «Разработка» |
| Что сервер читает или отправляет | «Приватность» |
| Интерфейс | скриншоты в `docs/screenshots/`, переснять `scripts/demo/shoot.sh` |
| Новая версия | бейдж наверху README, см. `git-workflow` |
| Скилы в `.claude/skills/` | «Как ведётся разработка» |

## Проверка

- Каждую команду из README запустить или сверить с кодом.
- Каждый путь и имя файла проверить: файл существует.
- Каждая картинка открывается по своей ссылке.
- Новые скриншоты снимаются только на вымышленных данных, см. скил `public-repo-hygiene`.
